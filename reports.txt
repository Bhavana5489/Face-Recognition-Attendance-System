================================================================================
                    GAZEPASS BIOMETRIC ATTENDANCE SYSTEM
                    TECHNICAL ARCHITECTURE & ALGORITHM REPORT
================================================================================

This document details the core web architecture, database schema, and the state 
of the Computer Vision / Machine Learning algorithms powering the biometric pipeline.

--------------------------------------------------------------------------------
1. SYSTEM ARCHITECTURE (FLASK & SQLITE3)
--------------------------------------------------------------------------------
Web Framework: Flask
- Acts as the primary API server, delivering UI templates (Admin, Registration, 
  Student modes) and handling state management.
- Utilizes a dedicated background thread for the CameraStream to ensure the 
  webcam is polled asynchronously without blocking API responses.
- The `/video_feed` endpoint streams real-time processed JPEG frames back to the 
  browser using multipart HTTP responses.
- Provides standard RESTful endpoints for starting/stopping attendance, managing 
  users, and retrieving statistics.

Database Layer: SQLite3 (gazepass.db)
- Stores student demographics, attendance logs, and facial templates.
- Embeddings generated by the AI models are serialized into raw BLOB formats 
  (numpy float32 arrays) and stored directly in the database. 
- In-memory Vector Search: Upon startup or registration, templates are loaded 
  into a VectorSearchEngine that utilizes exact NumPy cosine similarity matrix 
  multiplication for ultra-fast, dependency-free matching.

--------------------------------------------------------------------------------
2. FACE DETECTION & TRACKING (STATUS: WORKING WELL)
--------------------------------------------------------------------------------
Algorithm Used: OpenCV Zoo YuNet (2023mar) ONNX + ByteTrack

- Detection: YuNet is providing highly accurate, robust face detection bounding 
  boxes and preliminary 5-point landmarks. It functions perfectly under varying 
  conditions.
- Tracking: ByteTrack uses Bipartite Hungarian matching to assign persistent IDs 
  to detected faces, significantly reducing redundant frame-by-frame processing.
- Dense Landmarks: FaceX/OpenCV extracts a 98-point mesh to assist in precise 
  head pose and gaze evaluations.

--------------------------------------------------------------------------------
3. FACE RECOGNITION (STATUS: NEEDS IMPROVEMENT)
--------------------------------------------------------------------------------
Algorithm Used: OpenCV Zoo SFace (2021dec) ONNX

Process:
  1. The 5-point landmarks from YuNet are used to apply a deterministic affine 
     transform, cropping and aligning the face to a standardized 112x112 pixel tensor.
  2. The SFace model extracts a highly dense mathematical embedding.
  3. The system compares the live embedding against the in-memory SQLite gallery.

Current Issue:
- The recognizer is currently underperforming. Accuracy is not yet at an 
  acceptable level for seamless production use. It may be struggling with 
  similarity thresholding, model generalization, or producing overlapping 
  embeddings for distinct individuals.

--------------------------------------------------------------------------------
4. ANTI-SPOOFING & LIVENESS (STATUS: VERY BAD - HIGH FALSE POSITIVES)
--------------------------------------------------------------------------------
Algorithm Used: MiniFASNet Ensemble (V1SE & V2) + Active Gaze Challenge

Process:
  1. Passive PAD (Presentation Attack Detection): Evaluates the face crop and 
     contextual background scaling to detect physical photographs or digital screens.
  2. Active Challenge: Forces the user to look left/right or blink to satisfy 
     dynamic spatial and temporal liveness requirements.

Current Issue:
- The anti-spoofing module is failing severely due to an excessively high False 
  Positive rate. 
- It is aggressively flagging legitimate, real faces as "spoofed." 
- This effectively breaks the attendance pipeline because the liveness gate 
  rejects the user before the recognition phase can even occur. Threshold 
  re-calibration and environmental normalization (lighting/background adjustments) 
  are urgently required.

--------------------------------------------------------------------------------
5. REGISTRATION PROTOCOL
--------------------------------------------------------------------------------
- Implements a Multi-Pose Registration Engine enforcing the capture of 3 distinct 
  head poses (FRONT, UP, DOWN) over a minimum of 30 frames.
- Assesses Quality (Laplacian variance for sharpness, blur detection) before 
  allowing a template to be saved.
- Deletes legacy templates automatically when a user with the same name is 
  re-registered, ensuring the database remains clean.
